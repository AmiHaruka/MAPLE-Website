Machine Learning Potentials

MAPLE uses machine learning interatomic potentials (MLIPs) to compute energies and forces for its calculation workflows. The #model command selects a pretrained model. Its training data, reference level and chemical coverage determine which systems it can describe.

Model Selection Guide

Choosing the right model depends on your molecular system, required accuracy, and available computational resources. Here are general recommendations:

  • Organic molecules (H, C, N, O only): Start with ani2x for general use or ani1ccx when a coupled-cluster reference is needed for small molecules.
  • Organic molecules with S or halogens: ani2x covers H, C, N, O, F, S and Cl; MACE-OFF and GRACE-OFF also cover P, Br and I.
  • Systems with heavier elements: Use aimnet2 for its main-group element set, or MACE-OMol, MACE-Polar and SO3LR Tauri for wider coverage including metals.
  • Diverse chemical domains: Use uma with a task domain matching molecules, materials or catalysis.
  • Periodic materials / catalysis: UMA requires an explicit periodic task such as omat, oc20 or omc. Other periodic-capable models are listed in the capability matrix. UMA stress and virial output remain unavailable.
  • Charged or open-shell molecules: Use aimnet2 for charged singlets. AIMNet2-NSE, SO3LR, MACE-OMol, MACE-Polar and UMA with task=omol also accept spin multiplicity; FeNNix requires multiplicity 1.
  • Speed-critical workflows: Choose a smaller model within a suitable family; mace-off-23s and ANI models are options for organic systems.
  • Reference-level choice: Use ani1ccx for a CCSD(T)*/CBS reference within H/C/N/O chemistry. For DFT-trained models, select the reference level appropriate to the calculation.

Physical Corrections

ML potentials can be augmented with physical corrections to improve accuracy for specific interactions that are challenging for neural network models. Support is backend-specific; do not assume a correction is available for every model.

DFT-D4 Dispersion Correction

The D4 dispersion correction adds London dispersion interactions (van der Waals forces) to the ML potential energy. MAPLE supports this extra correction for non-periodic ANI calculations, except ani2dr, which already includes D3 dispersion.

#model = ani2x
#d4
#opt

Experimental Implicit Solvation

MAPLE's current implicit solvent path is an experimental GB-polar/QEq correction for single-point energies. It is configured through the #solv command with method=gbsa, an implicit solvent name, and experimental=true. See the Solvation page for details.

#model = uma
#solv(method=gbsa, implicit=water, experimental=true)
#sp

QEq Charges

The charge equilibration (QEq) method computes atomic partial charges used internally by the experimental implicit solvent correction. QEq charges are computed automatically when implicit solvation is enabled and do not require a separate command.

Important

Large models such as mace-off-23l and mace-omol-0 require significantly more GPU memory than smaller models. If you encounter out-of-memory errors, try switching to a smaller model variant (e.g., mace-off-23s) or use #device = cpu for systems that exceed your GPU memory.

Usage Examples

Below are complete input file examples demonstrating model selection for various scenarios.

General-purpose optimization with UMA (default: small v1.1 checkpoint, omol task)

# Uses uma-s-1p1 checkpoint and default inference interface
#model=uma
#opt(method=lbfgs, level=tight)

0 1
C    0.000000    0.000000    0.000000
O    1.200000    0.000000    0.000000
H   -0.540000    0.940000    0.000000
H   -0.540000   -0.940000    0.000000

UMA for inorganic materials (omat task)

#model=uma(task=omat)
#opt(method=lbfgs)

XYZ /path/to/material.xyz

UMA with CUDA turbo inference

# Opt in to the FAIR Chemistry turbo inference interface for repeated GPU evaluations
#model=uma(inference=turbo)
#ts(method=neb)

XYZ /path/to/reactant.xyz

XYZ /path/to/product.xyz

Charged-molecule calculation with AIMNet2

#model = aimnet2
#opt(method=lbfgs, level=extratight)

-1 1
C    0.000000    0.000000    0.000000
O    1.250000    0.000000    0.000000
O   -1.250000    0.000000    0.000000

Frequency calculation with MACE-OFF23

#model = mace-off-23m
#freq

XYZ /path/to/optimized_geometry.xyz

CPU-based calculation for large systems

#model = mace-off-23s
#device = cpu
#opt(level=loose)

XYZ /path/to/large_molecule.xyz
